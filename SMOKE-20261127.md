**Bug found and fixed during this run:** the first live run failed the
gofrantic board with `POST https://api.gofrantic.com/mcp returned HTTP 406`
and exited 1. Cause: the MCP endpoint requires the streamable-HTTP Accept
header (`application/json, text/event-stream`); `requests` sends `*/*` by
default. Fix: `boards.py` now sends that Accept header for the MCP call.
Re-run after the fix: exit 0, all three boards OK.

Test inputs (generated, not real media): 3× `testsrc` clips + a 440 Hz sine

Full-length test (10s clips → expected 30s):

```
$ python -m idawati_ops video --clips long1.mp4 long2.mp4 long3.mp4 \
    --audio tone.wav --text "animator: by. Labib" --out test-video-30s.mp4
Done: test-video-30s.mp4 (30.0s; 30s when each clip is 9s or longer)
duration=30.000000
```

**Bug found and fixed during this run:** the first video test produced
7.5s instead of 9s. Cause: the lavfi `color` source defaults to 25 fps
while the clips are 30 fps, and concatenating mixed-fps segments with
stream copy silently shortened the end card. Fix: the end-card input now
forces `r=30` and the end-card filter starts with `fps=30,format=yuv420p`.
Re-run: exactly 9.0s / 30.0s, 704x1248, H.264 + AAC, crop-fill (no blur
bands — verified by the filter chain, no `pad`/`blur` anywhere).
